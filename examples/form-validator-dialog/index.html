A11y Dialog integration example

Validated callback dialog

Open a native modal dialog that contains a semantic callback request form enhanced by A11y Form Validator. The example shows focus moving into the form, validation summary focus staying inside the dialog, and focus returning to the opener after close.

Scenario

A support teammate is reviewing an order and needs to schedule a priority callback without losing their place on the page.

User goal: open the request dialog, complete the required fields, fix validation errors from the summary, and return to the order overview when the dialog closes.

Try it

  • Open the callback dialog and confirm focus moves to Customer name.
  • Submit the empty form and confirm the validator focuses the error summary inside the dialog.
  • Use the summary links to move back to invalid fields.
  • Fix the fields, submit again, and confirm the dialog closes with focus restored to the opener.
  • Reopen the dialog and close it with Escape or Cancel to confirm the form state resets.

Accessibility notes

  • The modal uses a native <dialog> with a visible heading referenced by aria-labelledby.
  • The form keeps native labels, fieldsets, radios, a checkbox, and a submit button before validation is enhanced.
  • A11y Dialog moves initial focus to the first form field and restores focus to the opener after close.
  • A11y Form Validator renders inline messages, updates invalid fields, and focuses the error summary after blocked submits.
  • Summary links and generated inline errors remain inside the modal dialog, so Tab and Shift+Tab stay within the active task.
  • The demo CSS preserves visible focus styles, supports forced colors, and removes smooth scrolling for reduced-motion users.
  • Manual screen reader testing is still required for the browser and assistive technology combinations you support.

Developer notes

  • Import A11y Dialog from ../../dist/index.js and its package CSS from ../../dist/styles.css.
  • This static demo imports A11y Form Validator from a demo-local copy at ./vendor/a11y-form-validator/index.min.js.
  • The validator form root is [data-a11y-form-validator]; the dialog root is [data-a11y-dialog].
  • The validator uses createDefaultPreset(), which includes submit and blur validation plus the focusable error summary.
  • The submit event is prevented for the static demo, and the dialog closes only after the validator reports a valid submit.
