Scenario

A team admin reviews notification preferences before confirming them. The dialog has a visible heading, concise description, and close controls that are real buttons.

Review notification settings

Confirm whether these notification settings still match the way your team wants to receive product updates.

Focus moves to the primary confirmation button when the dialog opens. Closing restores focus to the review button.

Manual checks

Try it

  • Tab to Review notification settings and open it with Enter or Space.
  • Confirm focus moves to Confirm settings, the marked initial focus control.
  • Use Tab and Shift+Tab to confirm focus remains inside the open dialog.
  • Press Escape and confirm focus returns to the opener.
  • Open again and close with a button to confirm pointer and keyboard activation both work.

Developer copy path

Install and initialize

Install

npm install a11y-dialog

JavaScript

import { createA11yDialog } from "a11y-dialog";
import "a11y-dialog/styles.css";

const dialog = document.querySelector("#settings-dialog");
const trigger = document.querySelector("#settings-trigger");

if (dialog && trigger) {
  const instance = createA11yDialog(dialog);

  trigger.addEventListener("click", () => {
    instance.open(trigger);
  });
}

Required markup shape

<button id="settings-trigger" type="button">
  Review notification settings
</button>

<dialog
  class="a11y-dialog"
  id="settings-dialog"
  data-a11y-dialog
  aria-labelledby="settings-dialog-title"
  aria-describedby="settings-dialog-description"
>
  <div class="a11y-dialog__surface">
    <h2 id="settings-dialog-title">Review notification settings</h2>
    <p id="settings-dialog-description">Confirm the settings before continuing.</p>
    <button type="button" data-a11y-dialog-close>Close</button>
    <button type="button" data-a11y-dialog-close data-a11y-dialog-initial-focus>
      Confirm settings
    </button>
  </div>
</dialog>

API

Options and methods shown by this demo

Option or method Default Purpose
initialFocus null Can point to the first element focused on open. This demo uses data-a11y-dialog-initial-focus.
restoreFocus true Restores focus to the opener when the dialog closes and the opener is still connected.
closeOnEscape true Allows Escape and native cancel behavior to close the dialog.
closeOnBackdrop false Backdrop clicks do not close this basic demo unless the option is enabled.
open(trigger?) Method Opens the dialog and stores the opener for focus restoration.
close() Method Closes the dialog and runs the focus restoration behavior.

Accessibility behavior

What to verify

Keyboard

  • Enter and Space use native button activation.
  • Tab and Shift+Tab stay inside the open modal dialog.
  • Escape closes the dialog when closeOnEscape is true.

Screen reader notes

  • The dialog name comes from the visible heading referenced by aria-labelledby.
  • The description is connected with aria-describedby.
  • Manual testing is still needed in the browser and assistive technology combinations you support.

Focus

  • The marked initial focus button receives focus on open.
  • Focus returns to the opener after close when restoration is enabled.
  • The package includes a Tab containment fallback around native modal behavior.

Styling hooks

CSS classes and custom properties

Import a11y-dialog/styles.css or ../../dist/styles.css in these static examples to use the baseline layout, focus, backdrop, forced-colors, and reduced-motion styles.

Hook Purpose
.a11y-dialog Dialog root class for the optional baseline CSS.
.a11y-dialog__surface Inner layout wrapper used by the provided styles.
.a11y-dialog__button Baseline button treatment with visible focus styles.
--a11y-dialog-focus-color Customizes the focus outline color used by the package CSS.
--a11y-dialog-backdrop-color Customizes the native backdrop color.

Limits

What this package does not do

  • It does not polyfill native <dialog> for unsupported browsers.
  • It does not validate form fields or create error summaries.
  • It does not claim complete WCAG compliance for every integration.
  • Nested modal dialogs are outside the v1 support contract.
