Scenario

One last check before publishing

A creative lead is ready to publish a product campaign. They need to review the audience, schedule, and accessibility checks without losing their place in the studio dashboard.

Test guide

Try it

  1. Choose Automatic, CSS fallback, or No animation.
  2. Tab to Review and publish, then press Enter or Space.
  3. Confirm focus moves to Publish campaign inside the dialog.
  4. Close with Escape, the backdrop, or a visible close button and confirm focus returns.
  5. Enable reduced motion in the browser or operating system and confirm the automatic strategy becomes immediate.

Accessibility notes

Semantics and motion stay separate

Keyboard and focus

  • The opener and all dialog actions are native buttons.
  • Focus moves to the primary action after open.
  • Tab remains inside the modal and Escape closes it.
  • Close restores focus to the opener when it remains connected.

Name, description, and status

  • A visible heading provides the dialog name through aria-labelledby.
  • Concise supporting copy is connected with aria-describedby.
  • The persistent status reports whether the campaign was published or kept as a draft.

Reduced motion and fallback

  • The automatic strategy skips motion when reduced motion is requested.
  • Browsers without View Transitions use the optional CSS entry and exit path.
  • The dialog remains functional when the morph stylesheet cannot animate.

Developer notes

Copy the plugin contract, not the studio chrome

The page shell uses demo-* classes; the native dialog keeps the package classes and data attributes.

Imports and initialization

import { createA11yDialog } from "@vmitsaras/a11y-dialog";
import { createA11yDialogMorph } from "@vmitsaras/a11y-dialog/morph";
import "@vmitsaras/a11y-dialog/styles.css";
import "@vmitsaras/a11y-dialog/morph.css";

const instance = createA11yDialog(dialog, {
  closeOnBackdrop: true
});
const morph = createA11yDialogMorph(instance);

trigger.addEventListener("click", () => {
  morph.open(trigger);
});

Declarative morph options

<dialog
  data-a11y-dialog
  data-a11y-dialog-morph
  data-a11y-dialog-morph-strategy="auto"
  data-a11y-dialog-morph-source="#trigger"
  data-a11y-dialog-morph-duration="260"
  data-a11y-dialog-morph-direction="both"
  aria-labelledby="dialog-title"
>
  ...
</dialog>

Known limits

  • View Transition interpolation is controlled by the browser and needs visual testing in each target browser.
  • Direct calls to native dialog.close() bypass the core before-close lifecycle; use the core or morph instance.
  • This package does not polyfill native <dialog> or replace manual screen reader testing.
