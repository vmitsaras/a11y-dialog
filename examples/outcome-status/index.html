Install and initialize

Import core dialog behavior and the optional addon separately. The addon does not auto-initialize or create a hidden live region.

Install

npm install @vmitsaras/a11y-dialog

HTML

<p id="review-status" role="status"></p>

<dialog
  data-a11y-dialog
  data-a11y-dialog-status-target="#review-status"
  aria-labelledby="review-title"
>
  <h2 id="review-title">Review changes</h2>
  <button
    type="button"
    data-a11y-dialog-close
    data-a11y-dialog-outcome="save"
  >
    Save
  </button>
  <button type="button" data-a11y-dialog-close>
    Close
  </button>
</dialog>

JavaScript

import { createA11yDialog } from "@vmitsaras/a11y-dialog";
import { createA11yDialogOutcome } from "@vmitsaras/a11y-dialog/outcome";

const instance = createA11yDialog(dialog);
const outcome = createA11yDialogOutcome(dialog, {
  statusTarget: "#review-status",
  messages: {
    save: "Changes saved.",
    cancel: "No changes were made."
  },
  defaultMessage: "Review closed without saving."
});

trigger.addEventListener("click", () => {
  instance.open(trigger);
});

saveDraftButton.addEventListener("click", () => {
  outcome.setOutcome("draft", "Draft kept for later.");
  instance.close();
});

Addon API

Configure messages without changing dialog behavior

Outcome keys describe application results. They do not replace the core dialog lifecycle or add keyboard interaction.

Option Default Purpose
statusTarget null Existing element or selector that receives outcome text.
messages {} Maps short outcome keys to strings or message functions.
defaultMessage "Dialog closed." Reports a close without a captured outcome; use null to leave text unchanged.
openMessage null Optionally updates the same target when the dialog opens.
clearOnOpen false Clears the target on open when no open message is configured.
outcomeAttribute data-a11y-dialog-outcome Customizes the attribute read from close controls.
statusTargetAttribute data-a11y-dialog-status-target Customizes the dialog attribute that identifies the target.

Methods

setOutcome(key, message?)
Sets the next result before application code closes the dialog.
clearOutcome()
Removes a pending result without changing the current status text.
destroy()
Removes addon listeners and permits clean reinitialization.

Lifecycle event

a11y-dialog-outcome:update bubbles from the dialog after an update. Its detail includes the outcome key, resolved message, source element, reason, target, dialog, and instance.

Keyboard interaction

Core dialog keys stay unchanged

Key Behavior
Tab Moves forward through controls inside the open modal dialog.
Shift + Tab Moves backward through dialog controls.
Enter or Space Activates the focused native button and its configured outcome.
Escape Closes when enabled and uses the default outcome message.

Accessibility behavior

Keep semantics and announcement ownership explicit

What this example does

  • Uses a labelled native <dialog> and real buttons.
  • Places the status region outside the dialog so it remains exposed after close.
  • Restores focus before the outcome addon updates the status message.
  • Uses concise messages that identify saved, canceled, drafted, or dismissed results.
  • Preserves visible focus and forced-colors support from the package and demo CSS.

What authors still own

  • Choose whether the target should be live; the addon does not add role or aria-live.
  • Keep messages contextual without exposing sensitive application data.
  • Avoid an opening announcement that competes with the dialog name and description.
  • Test target browser and assistive technology combinations manually.
  • Use the async-action addon for pending, retry, and in-dialog failure states.

Limitations

This addon reports outcomes; it does not create them

  • No form submission, persistence, validation, analytics, or network work is performed.
  • No live region is generated, and no ARIA role is added automatically.
  • Literal attribute messages work, but mapped keys are easier to localize and maintain.
  • A target inside a closed dialog may no longer be exposed to assistive technology.
  • Native <dialog> support and screen reader announcements vary by browser and platform.
  • The package does not claim complete WCAG conformance.
