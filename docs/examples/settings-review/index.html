A11y Dialog example

Settings review dialog

Review workspace notification and security changes in a native modal dialog before saving them. The example focuses on initial focus, Escape close, status text, and focus restoration.

Try the settings review Review accessibility notes

Scenario

A SaaS admin is about to save changes that affect alerts and security reviews for the whole workspace. The dialog gives them one concise checkpoint before the settings are applied.

User goal: review the proposed settings, choose whether to save or cancel, and return to the same place in the page after the dialog closes.

Try it

  • Open the review dialog with the primary button.
  • Confirm focus moves to Save reviewed settings.
  • Use Tab and Shift+Tab to move through the dialog controls.
  • Close with Escape, Cancel, or Save and check the status message.
  • Confirm focus returns to Review workspace changes.

Accessibility notes

  • The dialog is a native <dialog> with a visible heading referenced by aria-labelledby.
  • The description is short and connected with aria-describedby.
  • Every opener and close control is a real button.
  • The primary save action is marked with data-a11y-dialog-initial-focus.
  • Escape closes the dialog because closeOnEscape keeps its default value of true.
  • The optional outcome addon reports cancel, close, and save results in the outside status region.
  • Manual screen reader testing is still required for your supported browser and assistive technology combinations.

Developer notes

  • Import core dialog behavior from ../../dist/index.js and the outcome addon from ../../dist/outcome.js.
  • Import package CSS from ../../dist/styles.css and demo-only CSS from ./styles.css.
  • Use [data-a11y-dialog] on the native dialog when using the package selectors.
  • Use [data-a11y-dialog-close] only on real buttons.
  • Outcome keys on close controls map to concise, user-facing messages without changing core dialog options.
