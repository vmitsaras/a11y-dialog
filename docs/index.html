Live optional addon

Morph an opener into a real modal dialog

Activate the button with a pointer, Enter, or Space. The automatic strategy uses a same-document View Transition when supported, otherwise the CSS scale and fade fallback. Close with either button, Escape, or the backdrop.

Focus moves into the native dialog after opening and returns to this button after closing. When reduced motion is requested, the addon skips the morph and keeps those focus changes immediate.

Install and initialize

Install

npm install @vmitsaras/a11y-dialog

JavaScript

import { createA11yDialog } from "@vmitsaras/a11y-dialog";
import "@vmitsaras/a11y-dialog/styles.css";

const dialog = document.querySelector("#settings-dialog");
const trigger = document.querySelector("#settings-trigger");

if (dialog && trigger) {
  const instance = createA11yDialog(dialog);

  trigger.addEventListener("click", () => {
    instance.open(trigger);
  });
}

Add morphing

import { createA11yDialogMorph } from "@vmitsaras/a11y-dialog/morph";
import "@vmitsaras/a11y-dialog/morph.css";

const morph = createA11yDialogMorph(instance, {
  source: trigger,
  strategy: "auto",
  direction: "both"
});

trigger.addEventListener("click", () => {
  morph.open(trigger);
});

Optional addon API

Configure the transition without changing core behavior

Importing @vmitsaras/a11y-dialog/morph is optional and side-effect free. The addon listens to the core cancelable before-open and before-close events, then delegates focus and dialog state back to the core instance.

Option Default Purpose
source Current opener An element, selector, or resolver for the source snapshot.
strategy "auto" Choose view-transition, css, none, or automatic fallback.
duration 180 Animation duration in milliseconds.
easing cubic-bezier(0.2, 0, 0, 1) Timing function shared by the View Transition and CSS paths.
direction "both" Animate opening, closing, or both state changes.
respectReducedMotion true Skip morphing when the user requests reduced motion.
onUnsupported "css" Use the CSS fallback or no animation when View Transitions are unavailable.

Declarative configuration

<dialog
  data-a11y-dialog
  data-a11y-dialog-morph
  data-a11y-dialog-morph-strategy="auto"
  data-a11y-dialog-morph-source="#settings-trigger"
  data-a11y-dialog-morph-duration="180"
  data-a11y-dialog-morph-direction="both"
  aria-labelledby="settings-title"
>
  ...
</dialog>

Transition lifecycle

  • a11y-dialog:before-open and before-close are cancelable.
  • View Transition names are unique per operation and cleaned after completion.
  • CSS close waits for transitionend with a timeout safety net.
  • Call morph.destroy() to remove addon-owned listeners and presentation state.

Implementation note

Developer note

Initialize createA11yDialog() with a labelled native <dialog>, then pass the activating control to open(trigger) so the default close behavior can return focus to that opener. Import the optional package CSS separately; the library does not polyfill <dialog> or provide form validation.

Accessibility behavior

What to verify

Keyboard

  • Enter and Space use native button activation.
  • Tab and Shift+Tab stay inside the open modal dialog.
  • Escape closes the dialog when closeOnEscape is true.

Focus

  • Focus moves to the configured initial target or the first useful fallback.
  • Focus returns to the opener when restoration is enabled and the opener remains connected.
  • Destroyed instances remove listeners and restore changed state.
  • The morph addon leaves core focus movement and restoration in control.

Limits

  • This package does not polyfill native <dialog>.
  • It does not validate form fields or create error summaries.
  • View Transition interpolation is browser-owned; unsupported browsers use CSS or no motion.
  • Direct native dialog.close() calls bypass addon lifecycle hooks.
  • Manual screen reader testing is still needed for supported browser and assistive technology pairs.
